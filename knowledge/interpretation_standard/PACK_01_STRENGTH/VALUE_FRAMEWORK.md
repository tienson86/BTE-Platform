# 1. Purpose

Each paragraph must provide **new information**.

Never repeat facts.

Never repeat the same insight in new adjectives.

This is the anti-padding contract for all interpretation packs.

---

# 2. Definition of Value

A paragraph has value when the customer knows something they did not know in the previous paragraph, and that something helps understanding or action.

A paragraph has no value when it only:

- restates the class
- restates the previous sentence with synonyms
- defines a term
- fills space to look premium

---

Each Customer Mode section spends a different information type.

If two sections could swap sentences without loss, one of them has no value.

---

# 4. No-Repeat Rules

1. The class name may appear in Conclusion, once more in Executive Summary, and only where grammar needs a referent. It must not open every paragraph.
2. The main causal trio (season / root / support) is told in Why. Later sections refer to “this standing” or “this force”, they do not re-teach Đắc Lệnh.
3. Advantages must not be Challenges with the word “but” removed.
4. Each Influence domain must add a domain constraint, not a synonym of personality.
5. Recommendations must not paste Influence.
6. Executive Summary must not paste Why.

---

# 5. The “New Fact” Test

Before keeping a paragraph, ask:

1. What is the new claim?
2. Which evidence supports it?
3. Which previous paragraph already said it?
4. If I delete it, does the customer lose a decision-relevant idea?

If (4) is no, delete it.

---

# 6. Anti-Duplication Examples

Fail (same information three times):

> You are Strong.
> Being Strong means you have strength.
> In career you are Strong so you are strong at work.

Pass (three different information types):

> You belong to the Strong category.
> Season and root back you, so you do not start empty.
> At work that becomes stamina under load; the cost is pushing past feedback.

---

# 7. Challenges vs Avoid

Challenges describe the cost.

Avoid tells the customer what not to do about that cost.

That is two values, not one.

Fail:

- Challenge: You may be stubborn.
- Avoid: Don’t be stubborn.

Pass:

- Challenge: Force can close the ear that needs correction.
- Avoid: Do not treat disagreement as a test you must win.

# 8. Domain Distinctness Matrix (Strength)

Use this as a reviewer grid. Each cell must be a different claim when the section is filled.

| Domain | Distinct question |
|--------|-------------------|
| Career | Where should load sit? |
| Wealth | How does force hold or release resources? |
| Marriage | How much space does force take in a bond? |
| Health | How does surplus or deficit show in energy? |
| Personality | What is the default stance toward the world? |
| Learning | How does this person take in new input? |
| Leadership | How does force land on other people? |
| Decision making | How fast, and how revisable, are choices? |

If Career and Leadership are identical, rewrite one.

---

# 9. Validation Mode Value

Mode A has a different value definition: completeness, not delight.

Repeating a rule ID in Evidence and Rule Trace is allowed because the jobs differ:

- Evidence: what exists
- Rule Trace: why it fired

Repeating the same why-fired paragraph twice is not allowed.

---

# 10. Padding Ban

Forbidden padding:

- restating the Product Manifesto
- teaching all of BaZi
- listing all five classes “for education”
- repeating luck twice
- adding quotes, poems, or slogans
- adding disclaimers in every section (one honest limit is enough)

---

# 11. Future Pack Reuse

Every later pack MUST declare an information budget table like section 3.

No pack may recycle Strength’s Advantages paragraph as Pattern’s Advantages.

Cross-pack reports must still add new information per pack, then compose without cloning.
