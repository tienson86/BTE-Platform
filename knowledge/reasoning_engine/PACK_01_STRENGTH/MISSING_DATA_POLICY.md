# Missing Data Policy

| Field | Value |
|-------|-------|
| Document | MISSING_DATA_POLICY |
| Version | 1.0.0 |

---

# 1. Principle

Absence of data is **not** evidence.

`luck data missing` must not become `luck has no effect`.

---

# 2. Availability states

| State | Meaning |
|-------|---------|
| `AVAILABLE` | Published and usable |
| `PARTIAL` | Present but incomplete (e.g. root present, hidden stems unknown) |
| `MISSING` | Wanted, not published |
| `NOT_APPLICABLE` | Dimension does not apply (drain inactive is AVAILABLE-inactive, not missing) |

Drain `0` / `inactive` is **available inactivity**, not missing drain. Drain **units** are ineligible; a “no leak” qualifier in Why is allowed only as “drain not active”, not as invented physiology.

---

# 3. Narrative effects

| State | Effect |
|-------|--------|
| MISSING luck | Luck section `insufficient_data`; no luck units |
| PARTIAL hidden stems | Why may use published root; do not claim hidden-root depth; confidence already penalized upstream |
| MISSING classification | fail / unmapped |
| NOT_APPLICABLE | skip that cause family |

---

# 4. Expansion ban

Do not replace missing luck with generic “your luck will change”.

Shorter interpretation is legal.
