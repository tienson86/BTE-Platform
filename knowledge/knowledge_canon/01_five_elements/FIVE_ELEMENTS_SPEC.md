# 1. Purpose

This specification defines the canonical academic data model for the Five Elements (Wu Xing) knowledge domain within the BTE Platform.

The purpose of this document is to standardize how Five Elements knowledge is represented, stored, validated, maintained, and referenced across the platform.

This specification defines the structure of the knowledge only.

It does not define:

- runtime logic
- interpretation rules
- scoring
- rule priority
- report generation

---

# 2. Scope

This module includes canonical knowledge for:

- Wood
- Fire
- Earth
- Metal
- Water

Including:

- Definitions
- Characteristics
- Natural Correspondences
- Relationships
- Classical References

---

# 3. Objectives

The Five Elements Knowledge Canon shall provide:

- A single source of truth for Five Elements knowledge.
- Standardized knowledge representation.
- Reusable academic assets.
- Stable references for Rule Database.
- Consistent terminology.

---

# 4. Knowledge Record Model

Each Five Element shall be represented by exactly one canonical Knowledge Record.

Each record shall be immutable by identity.

Each record shall have a globally unique Knowledge ID.

---

# 5. Required Fields

Every Knowledge Record shall contain the following sections.

## 5.1 Identity

- Knowledge ID
- Canonical Name
- Chinese Character
- Pinyin
- English Name

---

## 5.2 Classification

- Domain
- Category
- Subcategory

---

## 5.3 Definition

A concise academic definition.

---

## 5.4 Characteristics

Examples include:

- Nature
- Symbolism
- Growth Pattern
- Physical Representation

---

## 5.5 Correspondences

Each element shall define all traditional correspondences, including where applicable:

- Yin/Yang polarity
- Direction
- Season
- Climate
- Color
- Number
- Planet
- Heavenly Stem association
- Earthly Branch association
- Organ (Zang)
- Organ (Fu)
- Body Part
- Sense Organ
- Emotion
- Sound
- Taste
- Odor
- Development Stage
- Representative Animals
- Representative Materials

---

## 5.6 Relationships

Relationships shall be expressed independently from rules.

Supported relationship types include:

- Generates
- Generated By
- Controls
- Controlled By
- Overacts
- Overacted By
- Insults
- Insulted By

Relationships shall reference Knowledge IDs rather than names.

---

## 5.7 Classical References

Each record shall reference one or more authoritative academic sources.

Recommended sources include:

- Huang Di Nei Jing
- Di Tian Sui
- Yuan Hai Zi Ping
- San Ming Tong Hui
- Zi Ping Zhen Quan

Each reference shall contain:

- Reference ID
- Title
- Chapter (if available)
- Notes

---

## 5.8 Metadata

- Version
- Status
- Created Date
- Updated Date
- Reviewer
- Review Date

---

# 6. Knowledge Relationships

The Five Elements module shall support the following relationship models:

- Generating Cycle (Sheng)
- Controlling Cycle (Ke)
- Overacting Cycle (Cheng)
- Insulting Cycle (Wu)

Relationship data shall be stored separately from runtime rules.

---

# 7. Validation Rules

Every Knowledge Record shall satisfy the following requirements:

Identity

- Unique Knowledge ID
- Valid ID format

Structure

- All mandatory fields present
- Schema compliant

Academic

- Definition provided
- Characteristics provided
- Correspondences provided
- Relationships provided
- At least one academic reference

Integrity

- No duplicated correspondences
- No invalid relationship targets
- No circular self-reference unless explicitly defined

---

# 8. Naming Conventions

Canonical names shall be written in English.

Chinese names shall use Traditional Chinese characters where available.

Pinyin shall follow Hanyu Pinyin.

No abbreviations are permitted.

---

# 9. Versioning

This module follows Semantic Versioning.

- MAJOR — Breaking changes to the schema.
- MINOR — New optional fields or relationships.
- PATCH — Documentation or metadata corrections.

Knowledge IDs shall remain immutable across all versions.

# 11. Compliance

A Five Elements Knowledge Record shall not be considered **Official** unless it:

- conforms to this specification;
- passes schema validation;
- passes academic review;
- includes authoritative references;
- maintains complete relationship integrity.
