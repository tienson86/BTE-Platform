---

# 1. Purpose

This document defines the standards for all Five Elements Knowledge Records within the BTE Platform.

Knowledge Records are the canonical representation of academic knowledge and serve as the foundation for all downstream systems, including Rule Database, Interpretation Engine, Report Engine, and future AI services.

This document specifies how knowledge is organized, documented, and maintained. It does not contain interpretation logic or runtime rules.

---

# 2. Scope

This directory contains one canonical Knowledge Record for each of the Five Elements.

```
knowledge_records/

wood.json

fire.json

earth.json

metal.json

water.json
```

Each file represents exactly one element.

No duplicate or alternative records are permitted.

---

# 3. Design Principles

Every Knowledge Record shall follow these principles:

- Single Source of Truth
- Academic Accuracy
- Structured Representation
- Machine Readability
- Human Readability
- Stable Identity
- Reusability
- Traceability
- Extensibility

---

# 4. Record Structure

Each Knowledge Record shall conform to the Base Knowledge Schema and the Five Element Schema.

A record shall contain the following logical sections:

1. Identity
2. Classification
3. Definition
4. Characteristics
5. Correspondences
6. Relationships
7. References
8. Metadata
9. Validation
10. Revision History

No additional top-level sections are allowed unless introduced by a future schema version.

---

# 5. Identity Rules

Each record shall have:

- a globally unique Knowledge ID;
- one canonical English name;
- one Chinese name;
- one Pinyin representation.

Knowledge IDs are immutable.

Names may be updated only through an approved revision process.

---

# 6. Academic Requirements

Every record shall include:

- a precise academic definition;
- essential characteristics;
- complete traditional correspondences;
- all applicable Five Element relationships;
- references to authoritative classical sources.

Knowledge must be descriptive rather than interpretive.

---

# 7. Exclusions

Knowledge Records shall not contain:

- IF–THEN logic;
- scoring models;
- priority values;
- interpretation text;
- fortune-telling conclusions;
- runtime parameters;
- executable code.

These belong to other layers of the BTE Platform.

---

# 8. Relationship Policy

Relationships shall reference Knowledge IDs rather than textual names whenever possible.

Supported relationship types include:

- Generates
- Generated By
- Controls
- Controlled By
- Overacts
- Overacted By
- Insults
- Insulted By

Relationship data shall remain independent of Rule Database logic.

---

# 9. References

Every Official Knowledge Record shall cite one or more authoritative sources.

Preferred references include:

- Huang Di Nei Jing
- Zhou Yi
- Yuan Hai Zi Ping
- Di Tian Sui
- San Ming Tong Hui
- Zi Ping Zhen Quan
- Qiong Tong Bao Jian

References should identify the work and, where possible, the relevant chapter or section.

---

# 10. Versioning

Knowledge Records follow Semantic Versioning.

- MAJOR — Breaking structural changes.
- MINOR — New academic content.
- PATCH — Editorial or metadata corrections.

Knowledge IDs remain unchanged across versions.

---

# 11. Quality Criteria

A Knowledge Record is considered **Official** only when it satisfies all of the following:

- conforms to the applicable schemas;
- passes automated validation;
- passes academic review;
- contains complete mandatory fields;
- includes authoritative references;
- maintains relationship integrity.
