# 1. Purpose

This guide explains the academic meaning, authoring rules, and expected content for every field of the canonical Wood Knowledge Record.

The objective is to ensure that all contributors produce knowledge that is:

- academically consistent;
- structurally uniform;
- machine-readable;
- reusable across the BTE Platform.

This document complements:

- `FIVE_ELEMENTS_SPEC.md`
- `WOOD_SPEC.md`
- `knowledge_record.schema.json`
- `five_element.schema.json`

---

# 2. General Authoring Principles

Every field shall satisfy the following principles:

- factual rather than interpretive;
- based on classical sources whenever possible;
- concise and unambiguous;
- free from duplicated information;
- independent from runtime logic.

The Knowledge Record shall describe **what Wood is**, not **how Wood is interpreted**.

---

# 3. Identity

## Purpose

Provides the immutable identity of the Knowledge Record.

## Authoring Rules

- Never modify the Knowledge ID after publication.
- Canonical Name shall use the standard English term.
- Chinese Character shall use the traditional character "木".
- Pinyin shall follow Hanyu Pinyin.

## Must Not Include

- aliases;
- abbreviations;
- explanatory notes.

---

# 4. Classification

## Purpose

Places the record within the Knowledge Canon hierarchy.

## Authoring Rules

Classification shall identify:

- domain;
- category;
- subcategory.

Classification values shall remain stable across versions.

# 5. Definition

## Purpose

- destiny;
- fortune;
- health diagnosis;
- interpretation methods.

# 9. References

## Purpose

Documents the academic sources supporting the Knowledge Record.

Preferred references include:

- Huang Di Nei Jing
- Zhou Yi
- Yuan Hai Zi Ping
- Di Tian Sui
- San Ming Tong Hui
- Zi Ping Zhen Quan
- Qiong Tong Bao Jian

## Authoring Rules

Whenever possible include:

- work title;
- chapter;
- section;
- explanatory notes.

Avoid secondary or anonymous sources unless clearly identified.

# 10. Metadata

Metadata records the lifecycle of the Knowledge Record.

Typical fields include:

- version;
- status;
- created date;
- updated date;
- reviewer;
- review date.

Metadata shall never contain academic content.

---

# 11. Validation

Before publication verify:

## Structure

- Schema validation passes.
- Required fields exist.

## Academic Content

- Definition is complete.
- Characteristics are complete.
- Correspondences are complete.
- Relationships are complete.
- References are present.

## Integrity

- No duplicated information.
- No invalid relationships.
- No invalid identifiers.

---

# 12. Writing Style

Preferred style:

- objective;
- academic;
- concise;
- terminology-first.

Avoid:

- storytelling;
- prediction;
- speculation;
- interpretation;
- conversational language.

---

# 13. Common Authoring Mistakes

Do not:

- mix academic facts with interpretation;
- repeat information across multiple fields;
- store Rule Engine logic;
- assign scores or priorities;
- infer conclusions from correspondences.

Each field should contain only its intended type of knowledge.
