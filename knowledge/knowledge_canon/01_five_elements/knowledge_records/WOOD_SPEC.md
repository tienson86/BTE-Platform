# 1. Purpose

This specification defines the canonical academic requirements for the Wood (木) Knowledge Record within the BTE Knowledge Canon.

The purpose of this document is to ensure that every Wood Knowledge Record is complete, academically consistent, machine-readable, and reusable by all downstream components of the BTE Platform.

This specification defines **what knowledge must be represented**, not the actual knowledge values.

---

# 2. Scope

This specification applies only to the canonical Knowledge Record representing the Five Element **Wood (木)**.

Exactly one official Wood Knowledge Record shall exist within the Five Elements module.

---

# 3. Design Principles

The Wood Knowledge Record shall satisfy the following principles:

- Single Source of Truth
- Academic Accuracy
- Canonical Terminology
- Structured Representation
- Machine Readability
- Human Readability
- Traceability
- Extensibility
- Schema Compliance

---

# 4. Identity Requirements

The record shall contain immutable identity information, including:

- Knowledge ID
- Canonical Name
- Chinese Character
- Pinyin
- English Name

Identity values shall remain stable across all future versions.

---

# 5. Classification Requirements

The record shall define:

- Domain
- Category
- Subcategory

The classification shall uniquely identify the record as a Five Element Knowledge Asset.

---

# 6. Definition Requirements

The record shall include:

- A concise academic definition.
- Historical context where applicable.
- Conceptual boundaries of the Wood element.

The definition shall describe the concept rather than its applications.

---

# 7. Characteristics Requirements

The record shall document the intrinsic characteristics of Wood, including (where applicable):

- Nature
- Symbolism
- Growth Pattern
- Dynamic Behaviour
- Physical Representation
- Functional Qualities

Characteristics shall be descriptive and free from interpretive conclusions.

---

# 8. Correspondence Requirements

The record shall define all traditional correspondences associated with Wood.

The correspondence model shall include, where applicable:

- Yin/Yang polarity
- Direction
- Season
- Climate
- Color
- Number
- Planet
- Heavenly Stem association
- Earthly Branch association
- Zang organ
- Fu organ
- Body part
- Sense organ
- Emotion
- Taste
- Odor
- Sound
- Development stage
- Representative materials
- Representative plants
- Representative animals

Each correspondence shall be represented as structured data rather than free text whenever possible.

---

# 9. Relationship Requirements

The record shall define the canonical relationships between Wood and the other Four Elements.

Supported relationship types include:

- Generates
- Generated By
- Controls
- Controlled By
- Overacts
- Overacted By
- Insults
- Insulted By

Relationships shall reference Knowledge IDs rather than display names.

No Rule Engine logic shall be embedded.

---

# 10. Classical References

The record shall cite authoritative classical sources supporting the knowledge represented.

Preferred references include:

- Huang Di Nei Jing
- Zhou Yi
- Yuan Hai Zi Ping
- Di Tian Sui
- San Ming Tong Hui
- Zi Ping Zhen Quan
- Qiong Tong Bao Jian

Where available, references should include chapter or section information.

---

# 11. Metadata Requirements

The record shall include metadata describing its lifecycle, including:

- Version
- Status
- Created Date
- Updated Date
- Reviewer
- Review Date

Metadata shall not contain academic knowledge.

---

# 12. Validation Requirements

A Wood Knowledge Record shall satisfy all of the following before being designated **Official**:

## Structural Validation

- Conforms to `knowledge_record.schema.json`
- Conforms to `five_element.schema.json`

## Completeness Validation

- All mandatory fields populated
- Identity complete
- Classification complete
- Definition complete
- Characteristics complete
- Correspondences complete
- Relationships complete
- Metadata complete

## Academic Validation

- Terminology is consistent.
- Statements are internally consistent.
- References support the represented knowledge.
- No contradictory information exists.

## Integrity Validation

- Valid Knowledge IDs
- Valid relationship targets
- No duplicated correspondences
- No circular self-reference unless explicitly defined

---

# 13. Exclusions

The Wood Knowledge Record shall not contain:

- IF–THEN logic
- Rule definitions
- Priority values
- Scoring models
- Interpretation narratives
- Fortune-telling conclusions
- Runtime configuration
- Executable code

These concerns belong to other layers of the BTE Platform.

---

# 14. Downstream Dependencies

The Wood Knowledge Record is expected to be consumed by:

- Heavenly Stems
- Earthly Branches
- Hidden Stems
- Ten Gods
- Strength Analysis
- Pattern Analysis
- Useful God Analysis
- Combination Analysis
- Clash Analysis
- Seasonal Qi Analysis
- Rule Database
- Interpretation Engine
- Report Engine

---

# 15. Acceptance Criteria

A Wood Knowledge Record shall be considered **Official** only when:

- It complies with all applicable schemas.
- It satisfies this specification.
- It passes automated validation.
- It passes academic review.
- It maintains relationship integrity.
- It is approved through the BTE Knowledge Governance process.
