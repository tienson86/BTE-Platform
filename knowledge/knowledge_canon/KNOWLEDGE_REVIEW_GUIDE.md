# 1. Purpose

This document defines the official review process for all Knowledge Assets within the BTE Knowledge Canon.

The review process ensures that every published Knowledge Asset satisfies the architectural, academic, and governance requirements defined by the platform.

---

# 2. Objectives

The review process shall:

- Verify correctness
- Verify completeness
- Verify consistency
- Verify traceability
- Verify mapping integrity
- Verify reference quality
- Ensure publication readiness

---

# 3. Scope

This guide applies to:

- Knowledge Assets
- Knowledge Domains
- Metadata
- Relationships
- References
- Mapping Records
- Traceability Records

This guide does not apply to:

- Runtime Engines
- Source Code
- Report Rendering
- User Interface

---

# 4. Review Principles

Every review shall be:

- Objective
- Evidence-based
- Repeatable
- Transparent
- Traceable
- Version-aware
- Documented

Personal opinions shall never replace documented evidence.

---

# 5. Review Roles

## Author

Responsible for creating and maintaining the Knowledge Asset.

Responsibilities:

- Prepare complete documentation
- Provide references
- Resolve review comments

---

## Reviewer

Responsible for technical and academic verification.

Responsibilities:

- Validate structure
- Validate references
- Validate relationships
- Validate traceability
- Record findings

---

## Domain Expert

Responsible for domain-specific correctness.

Responsibilities:

- Verify academic interpretation
- Resolve conflicting viewpoints
- Recommend improvements

---

## Governance Committee

Responsible for publication approval.

Responsibilities:

- Final approval
- Policy enforcement
- Exception management

---

# 6. Review Workflow

```
Draft

↓

Self Review

↓

Technical Review

↓

Academic Review

↓

Quality Validation

↓

Governance Review

↓

Approved

↓

Published
```

If any stage fails, the Knowledge Asset returns to the Author for revision.

---

# 7. Review Stages

## Stage 1 – Self Review

The Author verifies:

- Required fields
- Formatting
- Metadata
- References

---

## Stage 2 – Technical Review

The Reviewer verifies:

- Template compliance
- Identifier validity
- Mapping integrity
- Relationship integrity

---

## Stage 3 – Academic Review

The Domain Expert verifies:

- Definition accuracy
- Terminology usage
- Evidence quality
- Interpretation consistency

---

## Stage 4 – Quality Validation

Validation tools verify:

- Required metadata
- Traceability
- Duplicate records
- Broken links
- Version consistency

---

## Stage 5 – Governance Review

Governance verifies:

- Compliance
- Publication readiness
- Documentation completeness

---

The following items shall be reviewed:

- Metadata
- Definition
- Classification
- Relationships
- References
- Evidence
- Mapping
- Traceability

- Governance

---

# 9. Review Criteria

Every Knowledge Asset shall be evaluated against:

| Criterion | Requirement |
|------------|-------------|
| Accuracy | Required |
| Completeness | Required |
| Consistency | Required |
| Traceability | Required |
| Mapping Integrity | Required |
| Reference Integrity | Required |
| Governance Compliance | Required |

---

# 10. Review Outcomes

Possible outcomes:

- Approved
- Approved with Minor Revisions
- Major Revision Required
- Rejected

Rejected assets shall not be published.

---

# 11. Review Comments

Every review comment shall include:

- Comment ID
- Reviewer
- Date
- Severity
- Description
- Recommendation
- Resolution Status

Comments shall remain part of the review history.

---

# 12. Issue Severity

| Severity | Description |
|----------|-------------|
| Critical | Publication blocked |
| Major | Must be corrected |
| Minor | Recommended improvement |
| Informational | No publication impact |

Critical issues always block approval.

---

# 13. Conflict Resolution

If reviewers disagree:

1. Preserve all review comments.
2. Record supporting evidence.
3. Escalate to the Domain Expert.
4. If unresolved, escalate to Governance.
5. Record the final decision.

Historical disagreements shall remain documented.

---

# 14. Publication Requirements

Publication requires:

- All mandatory fields complete
- No Critical issues
- No unresolved Major issues
- Review approval
- Governance approval
- Validation passed

---

# 15. Review Frequency

Knowledge Assets shall be reviewed:

- Before first publication
- After major revisions
- When primary references change
- During scheduled quality audits

---

# 16. Review Metrics

Recommended metrics:

- Review completion time
- Number of review cycles
- Critical issues found
- Major issues found
- Minor issues found
- Approval rate
- Average quality score

Metrics support continuous improvement.

---

# 17. Review Records

Each review shall produce a permanent record containing:

- Review ID
- Knowledge ID
- Version
- Reviewers
- Decision
- Comments
- Approval Date

Review records shall never be deleted.

---

# 18. Governance

The review process is governed by:

- Governance V1.0
- Knowledge Specification
- Knowledge Template
- Mapping Standard
- Traceability Specification
- Quality Standard

---

# 19. Compliance

All Knowledge Assets shall complete the official review process before publication.

No Knowledge Asset may bypass review.

Exceptions require documented Governance approval.
