# IMPROVEMENT_THEMES

| Field | Value |
|-------|-------|
| Rule | Group candidates — do not run one issue as an architecture |

Themes are buckets. Items stay in PRODUCT_BACKLOG.

---

## Themes

| Theme | Customer job | Items |
|-------|--------------|-------|
| **Narrative Quality** | Sentences feel like *this* life, not a template | PB-004 · PB-007 · PB-013 |
| **Theme Quality** | Close matches published class; no leak | PB-002 · PB-003 · PB-005 |
| **Context Adaptation** | Right audience / capacity (parent, conserving adult) | PB-001 · PB-006 |
| **Product Experience** | Real humans complete RC3 | PB-008 |
| **Knowledge Depth** | Richer catalog when features already speak | PB-012 (Deferred) |
| **Packaging** | What is sold, what is hidden, what is Unavailable | PB-010 · PB-011 |
| **Commercial Expansion** | More bound charts / later SKUs — not new doctrine | PB-009 |

Not used as a theme: “Engine Quality.” Engine work is rejected or deferred (DECISION_LOG).

---

## Why themes not modules

| Wrong frame | Right frame |
|-------------|-------------|
| “Fix Score Engine” | Customer does not buy a score |
| “Add Persona Engine” | Rejected — theme + context already route |
| “Publish all Knowledge” | Low live CX · PB-012 Deferred |

## Sequencing

```text
Context Adaptation (PB-001)
    → Theme Quality (PB-002, PB-003, optionally PB-005)
        → Narrative polish (PB-004, PB-007)
            → Experience / binds (PB-008, PB-009)
                → Packaging / Knowledge later
```
