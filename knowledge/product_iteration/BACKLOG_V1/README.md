## Purpose

Decide **what to improve next** by customer value and ROI — then feed one item into the iteration process.

```
Discovery / Quality evidence
        ↓
PRODUCT BACKLOG V1.0     ← YOU ARE HERE
        ↓
ITERATION_00N (one item)
        ↓
Analytics ledger (scores · ROI · regression)
```

## Iteration philosophy

1. One official backlog.  
2. One item in **In Progress**.  
3. ROI before code.  
4. Revalidate target + regress CASE_0001.  
5. Record observed ROI.  
6. Personas are review lenses — not a runtime.

Process: `../ITERATION_001/ITERATION_PROCESS.md`.

---

## ROI-driven improvement

An item is Ready only if:

- a customer benefit is stated  
- layer is named  
- expected ROI is estimated  
- regression set includes Frozen Golden  
- it is **not** an engine/Knowledge invent

Low-ROI engine/Knowledge items stay **Deferred** or **Rejected** (see DECISION_LOG).

## Golden Dataset relationship

Golden Dataset V1 is the **laboratory**. CASE_0001 is the regression contract.

## Quality Gate relationship

Quality Gates remain the **release** authority (RC0→V1.1).

If the frozen Quality Gate file and later EPIC scores disagree, **do not edit the gate file**. Record the product evidence in [RELEASE_BOARD.md](RELEASE_BOARD.md) and [DECISION_LOG.md](DECISION_LOG.md).
