# Design Checklist Master

**Path:** `design/DESIGN_CHECKLIST_MASTER.md`  
**Version:** V1.0.0  

Use for every Knowledge Record design (in addition to pack `DESIGN_CHECKLIST.md`).

---

## Academic

- [ ] Purpose / Scope / Excluded Scope stated  
- [ ] Definition present or explicitly `TODO_REVIEW`  
- [ ] Characteristics slots addressed or deferred  
- [ ] Canonical School noted or `TODO_REVIEW`  
- [ ] Academic Sources listed as Foundation `REF-*` only  
- [ ] No invented classical quotations  
- [ ] Module boundary respected (no strength/pattern/etc. leakage)  

---

## Technical

- [ ] Planning ID correct  
- [ ] Knowledge ID = `PENDING_GLOBAL_ALLOCATOR` until issued  
- [ ] Relationships use Planning ID / issued KNO only  
- [ ] File naming follows Design Rules  
- [ ] Pack README / DESIGN_ORDER updated  
- [ ] No Official JSON created prematurely  

---

## Governance

- [ ] Ownership Matrix status Resolved (or Blocked documented)  
- [ ] Link-only vs module-owned confirmed  
- [ ] Review workflow followed  
- [ ] CHANGELOG / progress boards updated when required  

---

## Compiler

- [ ] Design sections mappable via `RECORD_MAPPING_TEMPLATE`  
- [ ] Definition is compile-ready as a single string  
- [ ] Characteristics keys limited to schema-allowed set  
- [ ] References shaped for `references[]`  

---

## Validation

- [ ] Pack validation checklist considered  
- [ ] Master checklist complete  
- [ ] Technical Review notes recorded  
- [ ] Academic Review notes recorded  

---

## Release

- [ ] Approved for compiler input (if JSON-eligible)  
- [ ] Or marked link-only (Canon / Foundation) with no BaZi JSON  
- [ ] Freeze status updated when pack closes
