# 1. Purpose

This specification defines the academic scope, structural requirements, validation rules, and governance principles for the Fundamental Knowledge module within the BTE BaZi Knowledge Canon.

The purpose of this specification is to establish a single, canonical foundation for all subsequent BaZi knowledge modules.

---

# 2. Module Mission

The Fundamental Knowledge module shall provide the immutable academic concepts required by every BaZi analysis process.

This module defines concepts only.

It does not define interpretation.

It does not define analytical rules.

It does not define scoring.

---

# 3. Scope

The module shall contain canonical knowledge describing the foundations of BaZi theory.

Typical knowledge domains include:

- Yin and Yang
- Five Elements (Wu Xing)
- Heavenly Stems
- Earthly Branches
- Hidden Stems
- Stem–Branch system
- Qi
- Seasonal Qi
- Chang Sheng (Twelve Growth Phases)
- Five Element relationships
- Classical terminology
- Fundamental cosmological principles

---

# 4. Explicit Exclusions

The following topics are prohibited within this module:

- Strength analysis
- Temperature analysis

- Useful God determination
- Ten Gods interpretation
- Combination rules
- Clash rules
- Punishment rules
- Harm rules

- Luck cycle interpretation
- Marriage analysis
- Wealth analysis
- Career analysis
- Health analysis
- Children analysis
- Rule Engine logic
- Scoring systems
- Runtime parameters
- AI prompts

# 5. Knowledge Categories

Knowledge Records shall belong to one of the following categories:

- Fundamental Concept
- Fundamental Relationship
- Fundamental Classification
- Canonical Definition
- Classical Principle
- Terminology
- Cosmological Concept

Each record shall belong to exactly one primary category.

# 7. Relationship Rules

Knowledge Records may establish only academic relationships.

Allowed relationship types include:

- Defines
- Depends On
- Related To
- Parent Of
- Child Of
- Generates
- Generated By
- Controls
- Controlled By

Relationship targets shall always reference canonical Knowledge IDs.

# 9. Terminology Policy

Canonical terminology shall always be taken from the Terminology Library.

Knowledge Records shall not redefine canonical terms.

Aliases shall never replace canonical terminology.

# 11. Knowledge Boundaries

This module provides only fundamental knowledge.

Other modules shall extend this knowledge rather than redefine it.

Fundamental concepts shall exist in one location only.
