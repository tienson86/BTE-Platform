# ADR-0001 — Layered architecture and one-engine responsibility

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-09 |
| **Platform** | 1.0.0 |
| **Deciders** | Architecture Board |

---

## Context

BTE combines calendar math, BaZi charting, scoring, pattern logic, knowledge evaluation, decision, luck, interpretation, and reporting. Mixing these in one module produced hidden coupling and untestable shortcuts.

---

## Decision

The platform is strictly layered:

```
Knowledge → Rule → Calendar / Bazi / Score / Pattern
  → Analysis → Decision → Luck → Interpretation → Report → API
```

Each engine has one responsibility. Engines communicate through result objects or engine context. Downstream engines MUST NOT be imported by upstream engines.

---

## Consequences

Positive: independent tests, clear ownership, commercial maintainability.

Negative: more wrappers and snapshot copies.

Rejected alternative: a single “smart report” engine that recalculates Useful God while formatting text.
