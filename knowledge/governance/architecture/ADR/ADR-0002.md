# ADR-0002 — Canonical pipelines as the only supported execution model

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-09 |
| **Platform** | 1.0.0 |
| **Deciders** | Architecture Board |

---

## Context

Individual analyzers and report builders historically ran ad hoc. Order drift produced non-deterministic and non-auditable outcomes.

---

## Decision

For each package class there is exactly one supported orchestration path:

| Class | Pipeline | Version |
|-------|----------|---------|
| Analysis Knowledge | `canonical_analysis_pipeline` | 2.0.0 |
| Decision | `canonical_decision_pipeline` | 1.0.0 |
| Luck | `canonical_luck_pipeline` | 1.0.0 |
| Interpretation | `canonical_interpretation_pipeline` | 1.0.0 |
| Report | `canonical_report_pipeline` | 1.0.0 |

Stages execute once, in dependency order, publishing declared outputs only. Future stages (publisher, delivery, print, AI rewrite, AX-2 luck/interpretation/report slots) are registered and disabled.

Released components remain independently importable for backward compatibility. New work MUST bind the canonical pipeline.

---

## Consequences

Positive: one official result shape, contract verification, traces and audits.

Negative: more orchestration code per engine.

Rejected alternative: allowing UI or API to call RE-3 or IE-3 directly as the supported product path.
