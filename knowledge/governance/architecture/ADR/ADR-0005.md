# ADR-0005 — Result objects, contracts, trace, audit, diagnostics

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-09 |
| **Platform** | 1.0.0 |
| **Deciders** | Architecture Board |

---

## Context

Tuple and dict returns hid schema drift. Exceptions leaked across API boundaries. Executions were not machine-auditable.

---

## Decision

1. Engines and pipelines return dataclass result objects.
2. Each canonical pipeline publishes a versioned contract function.
3. Before a stage runs, verifiers check schema, SemVer, dependencies, and declared I/O. Violations stop the run.
4. Every canonical `run()` publishes machine-readable **trace**, **audit**, and **diagnostics**.
5. `run()` never raises to callers; failures become diagnostic codes (`PIPE-FAIL`, `CONTRACT-VIOLATION`, …).
6. Outputs are append-only. Duplicate publication is a hard error.

Multiple historical types may share a name (for example RE-1 empty `CanonicalReportResult` vs RX-1 pipeline `CanonicalReportResult`). The **canonical pipeline result** is the only official output for new Report work. Older types remain for backward compatibility.

---

## Consequences

Positive: determinism tests, checksummable contracts, safe API boundaries.

Negative: three coexisting Report result types until a future MAJOR cleanup.

Rejected alternative: raising raw exceptions from pipeline `run()` and logging only.
