# ADR-0003 — Knowledge Package system and sealed checksums

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-09 |
| **Platform** | 1.0.0 |
| **Deciders** | Architecture Board + Knowledge Board |

---

## Context

Hard-coded `if/elif` analytical trees inside Python made schools, languages, and evidence unreviewable. CSV Rule Database remains the store; packages add identity, SemVer, evidence, reasoning, and immutability.

---

## Decision

1. Business rules live in the Knowledge / Rule Database and Knowledge Packages, not in engine control flow that replaces records.
2. Packages follow KD-3: immutable `package_id`, SemVer `package_version`, schema `2.0.0`, SHA-256 checksum, lifecycle ending in `released`.
3. Engines read through loaders. They never write, update, or delete database files.
4. Sealed checksums are part of the Platform v1.0 release manifest. In-place edits of released packages are forbidden.

Foundation-era sealed packages: `bz_01` … `bz_09`.

---

## Consequences

Positive: reproducible knowledge, independent deployability, reviewable evidence.

Negative: authoring overhead; two-pass checksum discipline.

Rejected alternative: embedding Useful God trees in Decision Engine Python.
