# 1. Purpose

This Standard Operating Procedure (SOP) defines the official review process for all Knowledge Assets before they are approved for release.

The objectives are:

- Verify correctness.
- Ensure consistency.
- Maintain governance compliance.
- Improve knowledge quality.
- Support traceability.

No Knowledge Asset may enter the Official state without completing this procedure.

---

# 2. Scope

This procedure applies to:

- Knowledge Chapters
- Rule Database
- Rule Collections
- Sentence Library
- Phrase Library
- Case Studies
- Terminology Registry
- Reference Registry
- Governance Documents
- Report Templates

---

# 3. Preconditions

Before review begins:

- Draft completed
- Metadata completed
- Asset ID assigned
- Required references attached
- Self-validation passed
- Author approval for submission

---

# 4. Inputs

Required inputs:

| Input | Description |
|------|-------------|
| Draft Asset | Knowledge Asset under review |
| Metadata | Metadata file |
| Validation Checklist | Self validation results |
| References | Supporting references |
| Related Assets | Dependency information |

---

# 5. Roles and Responsibilities

| Role | Responsibility |
|------|----------------|
| Author | Submit asset and respond to review comments |
| Technical Reviewer | Validate structure and formatting |
| Knowledge Reviewer | Validate knowledge accuracy |
| Editorial Reviewer | Validate language and style |
| Governance Reviewer | Validate compliance |
| Approver | Final approval |

A reviewer SHALL NOT review their own work.

---

# 6. Procedure Steps

## Step 1 — Review Assignment

Assign reviewers according to asset type and knowledge domain.

Deliverables:

- Review ID
- Assigned reviewers
- Review schedule

---

## Step 2 — Technical Review

Verify:

- Directory structure
- Markdown Standard
- Metadata
- Asset IDs
- Cross references
- Templates

---

## Step 3 — Knowledge Review

Verify:

- Accuracy
- Completeness
- Logic
- Rule consistency
- Internal consistency

---

## Step 4 — Editorial Review

Verify:

- Grammar
- Style Guide
- Terminology
- Readability
- Examples
- Tables
- Diagrams

---

## Step 5 — Governance Review

Verify:

- Standards compliance
- Policy compliance
- Traceability
- Versioning
- Registry references

---

## Step 6 — Consolidate Findings

Collect all review comments.

Each finding SHALL include:

- Finding ID
- Severity
- Description
- Recommendation

Severity Levels:

- Critical
- Major
- Minor
- Suggestion

---

## Step 7 — Author Revision

The author addresses all findings.

Each resolved finding SHALL be marked as:

- Resolved
- Partially Resolved
- Rejected (with justification)

---

## Step 8 — Verification Review

Reviewers verify corrections.

If unresolved Critical issues remain, the asset SHALL return to Step 7.

---

## Step 9 — Final Approval

Governance confirms:

- All mandatory reviews completed
- Critical findings resolved
- Major findings resolved or accepted
- Compliance satisfied

---

# 7. Outputs

Successful completion produces:

- Approved Review Report
- Review Checklist
- Finding Log
- Updated Asset
- Approval Record

---

# 8. Validation

Before approval verify:

- Review complete
- Metadata valid
- References validated
- Terminology compliant
- Rule Mapping complete
- Traceability complete
- Quality Score achieved

---

# 9. Exceptions

Emergency reviews may follow an accelerated workflow.

The following SHALL still be completed:

- Technical Review
- Governance Review
- Post-release verification
