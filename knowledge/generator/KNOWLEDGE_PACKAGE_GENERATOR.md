# BTE Knowledge Package Generator

| Field | Value |
|-------|-------|
| **Document** | KNOWLEDGE_PACKAGE_GENERATOR |
| **Version** | 1.0.0 |
| **Status** | Canonical Foundation |
| **Scope** | Specification only — no runtime generator |
| **Schema** | `generator.schema.json`, `package_profile.schema.json` |

This is **not** a Knowledge Package. This is **not** a Rule Package.

It is the master specification from which every future Knowledge Package is produced.

---

## 1. Purpose

After Generator v1.0, every package — Strength successors, Seasonal, Temperature, Pattern, Combination, Useful God, Shen Sha, Feng Shui, Qi Men, I Ching, Interpretation, Report, Metadata, Sentence Library — MUST be generated from a **Package Profile** through the **Generation Pipeline**.

The Generator:

1. Enforces KD-1 → KD-4 and KX-1A → KX-1C standards.
2. Emits KD-3 package anatomy only.
3. Leaves engines, API, contracts, Rule Database, Golden Dataset, and existing packages untouched.
4. Supports 100,000+ knowledge records, unlimited future package types (via a new `generator_version`), multilingual packages, multiple domains, deterministic generation, independent releases, future AI-assisted generation, and a future visual package builder.

## 2. Position in the platform

```
Taxonomy / Ontology (KD-2)
        ↓
Package Specification (KD-3)
        ↓
Authoring & Validation Pipeline (KD-4)
        ↓
Knowledge Package Generator (this document)
        ↓
Evidence (KX-1B) + Reasoning (KX-1C)
        ↓
Released Knowledge Package
        ↓
Interpretation → Report
```

Engines consume **released packages**. They never consume generator profiles.

Strength Core (`bz_01_strength_core`) is the **reference implementation** of an analytical package. It is not regenerated by this sprint. Instance profile `examples/strength_profile.json` is retrospective documentation only.

## 4. Profile system

A **profile** is the single input that drives generation.

### 4.1 Required profile fields

| Field | Meaning |
|-------|---------|
| `package_id` | Immutable KD-3 id (or `{{PACKAGE_ID}}` on type profiles) |
| `package_name` | Display name |
| `package_type` | KD-3 type enum |
| `domain` | `{ domain_id }` from `knowledge/taxonomy/domains.json` |
| `taxonomy` | Taxonomy version + source |
| `ontology` | Ontology version + concept ids |
| `target_rule_count` | `{ minimum, recommended, maximum, target }` |
| `evidence_required` | Whether KX-1B evidence folder is mandatory |
| `reasoning_required` | Whether KX-1C reasoning folder is mandatory |
| `example_required` | Whether examples are mandatory |
| `validation_profile` | `PVP-MINIMAL` \| `PVP-STANDARD` \| `PVP-RELEASE` |
| `quality_target` | `bronze` \| `silver` \| `gold` \| `platinum` |
| `package_version` | Initial SemVer |

Schema: `package_profile.schema.json`.

### 4.2 Profile kinds

| Kind | Id pattern | Role |
|------|------------|------|
| common | `GEN-PROFILE-COMMON` | Shared defaults |
| type | `GEN-TYPE-*` | Reusable package-type behavior |
| instance | `GEN-INST-*` | One concrete future (or retrospective) package |

### 4.3 Inheritance

```
GEN-PROFILE-COMMON
  ├── GEN-TYPE-ANALYTICAL
  │     ├── GEN-INST-STRENGTH
  │     ├── GEN-INST-SEASONAL
  │     ├── GEN-INST-PATTERN
  │     └── GEN-INST-SHENSHA
  ├── GEN-TYPE-INTERPRETATION
  ├── GEN-TYPE-REPORT
  ├── GEN-TYPE-METADATA
  └── GEN-TYPE-SENTENCE
```

Merge rules (deterministic):

1. Resolve parent chain first (no cycles — constraint GC-INHERIT-ACYCLIC).
2. Child scalar/object keys override parent.
3. Arrays replace unless `inherit_arrays` = `append`.
4. After merge, sort object keys is not required in stored JSON; validation compares canonicalized JSON (locale `C` key sort) when checking determinism.
5. Placeholders (`{{PACKAGE_ID}}`, …) resolve only on instance profiles or at skeleton stage.

### 4.4 Common base (`GEN-PROFILE-COMMON`)

| Field | Default |
|-------|---------|
| `schema_version` | `2.0.0` |
| `knowledge_version` | `1.0.0` |
| `package_spec_version` | `1.0.0` |

| `status` at emit | `draft` |
| `language` | `vi` |
| `compatible_with_v1` | `true` |
| `evidence_required` | `false` |

Type profiles override component and completeness flags. Instance profiles override identity, domain, counts, and prefixes.

## 5. Generation pipeline

Canonical order (`GEN-PIPELINE-V1`):

```
Profile
  → Package Skeleton
  → Metadata
  → Manifest
  → Rules
  → Evidence
  → Reasoning
  → Examples
  → Tests
  → Validation
  → Documentation
  → Release Candidate
  → Released Package
```

No stage may be skipped. Stages that are N/A for a type (e.g. rules for a metadata package) still **run** and record `not_applicable` with a typed reason.

Full contracts: `generation_pipeline.md`.

Workflow mapping to KD-4 states: `generation_workflow.md`.

## 6. Templates

`generation_templates/` are the only allowed skeletons for generated files. They reference:

| Template | Standard |
|----------|----------|
| `package_profile.json` | This generator |
| `package_manifest.json` | KD-3 `package_manifest.schema.json` |
| `package_metadata.json` | KD-3 / KD-4 metadata |
| `package_release.json` | KD-3 `package_release.schema.json` |
| `rule_template.json` | KD-1 object + KD-4 rule template |
| `evidence_template.json` | KX-1B Evidence Bundle |
| `reasoning_template.json` | KX-1C graph/node/edge/chain/trace |
| `example_template.json` | Package-local examples (not Golden Dataset) |
| `validation_template.json` | KD-3 / KD-4 `VALIDATION.json` |
| `documentation_template.json` | README / CHANGELOG / overview |

Authoring copies under `knowledge/authoring/templates/` remain valid. Generator templates are the **superset** used for new official packages (they add evidence + reasoning).

## 8. AI generation

AI agents MAY produce **draft** packages from profiles and templates.

AI agents MUST NOT:

- modify engines, API, or contracts
- modify existing released packages (including Strength Core)
- invent unpublished analytical theory
- seal a package as `released`
- edit Golden Dataset, snapshots, or expected outputs

Human Technical Review, Domain Review, and Release Manager approval remain mandatory (KD-4).

Full policy: `documentation/ai_generation.md`.
