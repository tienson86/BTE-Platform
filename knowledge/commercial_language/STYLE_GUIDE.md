# STYLE_GUIDE — Commercial Language Layer V1.2

Version: 1.2.0

Quick checklist for composers and reviewers.

---

## Always

- [ ] Trace paragraph to claim-plan slot(s)  
- [ ] Answer So what? / Why care? / What do?  
- [ ] Use plain language first  
- [ ] Keep consultant voice  
- [ ] Preserve unresolved / nuance honestly  
- [ ] Keep chart-specific theme (no foreign-case insight)  

## Never

- [ ] Ship claim keys or enums to Customer Mode  
- [ ] Invent titles, income, timing, diagnoses  
- [ ] Average or silently pick conflicting domain facts  
- [ ] Paste textbook Ten Gods definitions  
- [ ] Reuse another case’s memory line  
- [ ] Modify upstream facts to make prose easier  

---

## Section readiness rubric (0–2 each)

| Criterion | 0 | 1 | 2 |
|-----------|---|---|---|
| Clarity | Jargon / keys | Mostly plain | Immediately clear |
| Trust | Hides tension / overclaims | Mostly honest | Bounded + nuanced |
| Value | No decision change | Mild insight | Changes self-view or next step |
| Action | None | Vague | Concrete do/avoid |
| Memory | Forgettable | Weak tagline | One sticky true line |

Commercial readiness for a feature body: average ≥ 1.5 and no Never-list violations.

---

## Recognition language (Layer 3) — short rules

Recognition is not praise. It is accurate mirroring:

> “Khi đọc phần này, bạn nhận ra mình thường…”

Must be supported by operating_style / identity_core / primary theme.  
If you cannot point to a claim → do not write recognition.
