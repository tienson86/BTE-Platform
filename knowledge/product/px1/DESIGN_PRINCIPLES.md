# Design Principles — Result Experience V2

Version: 2.0.0  
Status: **OFFICIAL — Design Only**  
Date: 2026-08-09  
Sprint: Phase X · PX-1  
Depends on: Product Manifesto · Experience Principles · Brand Language

---

## 1. Purpose

These principles govern every Result Experience V2 decision.

If a future layout, card, or copy choice conflicts with these principles, the principle wins.

---

## 2. Primary identity

The Result Page is a **consultation session**, not a data screen.

The user should feel:

> “Một chuyên gia đang dẫn tôi hiểu tình huống, rồi mới đề xuất việc nên làm.”

Never:

> “Một hệ thống vừa đổ dữ liệu lên bảng điều khiển.”

---

## 3. Experience pyramid

```
Trust
  ↓
Understanding
  ↓
Insight
  ↓
Action
  ↓
Reflection
```

Technology supports the experience.  
Technology never becomes the experience.

---

## 4. Mandatory principles

### P1 — Consultant, not calculator

Lead with identity, judgment, and advice.  
Charts, pillars, schema, and metadata are evidence — never the opening.

### P2 — Explain before the user acts

Every recommendation answers **Vì sao → Kết quả kỳ vọng → Việc cần làm**.  
Explanation lives *inside* the recommendation, not behind a wall of charts.

### P3 — One next understanding

Each section answers one question.  
The page always implies: “Tiếp theo bạn cần hiểu điều gì?”

### P4 — Advice before apparatus

```
Tóm tắt
  ↓
Định hướng
  ↓
Cảnh báo
  ↓
Lĩnh vực đời sống
  ↓
Biểu đồ
  ↓
Kỹ thuật
```

Charts never appear before recommendations.

### P5 — Progressive disclosure

```
Preview
  ↓
Expand
  ↓
Detail
```

First load must be readable in one calm pass.  
Depth is invited, never forced.

### P6 — Vietnamese for humans

Everything the user can see is Vietnamese.  
No English titles. No mixed labels. No engine IDs. No internal schema names.

### P7 — Calm over excitement

No urgency theatre.  
No decorative noise.  
No competing primary actions.

### P8 — Confidence without certainty

Speak with professional confidence.  
Never claim absolute fate.  
Name uncertainty when it exists.

### P9 — One primary action per view

Exactly one Primary CTA.  
Secondary and tertiary actions stay quieter.

### P10 — Attention is scarce

Every block must justify its presence.  
If it does not improve trust, understanding, or action — remove or collapse it.

### P11 — Tokens are frozen

Typography sizes, spacing scale, color roles, elevation, and contrast come from Visual Language and Design System.

PX-1 defines **roles and usage**.  
PX-1 does not invent new visual values.

### P12 — Reading order is invariant

Desktop, Tablet, and Mobile keep the same section order.  
Responsive layout may stack. It may not reorder meaning.

---

## 5. Anti-principles (forbidden)

| Forbidden | Why it fails |
|-----------|--------------|
| Dashboard of equal cards | No consultant lead |
| Technical metadata in Hero | Breaks trust posture |
| Charts before advice | Calculator feel |
| English / mixed UI labels | Breaks commercial voice |
| Engine terminology in first viewport | Alienates the customer |
| Multiple primary CTAs | Decision freeze |
| Knowledge competing with advice | Education interrupts action |
| Mystery instead of explanation | Superstition, not BTE |
| Decorating to create importance | Hierarchy must come from meaning |

---

## 6. Decision rule

When options conflict, choose the one that:

1. Strengthens trust  
2. Improves understanding  
3. Reduces cognitive load  
4. Makes the next action clearer  
5. Keeps Vietnamese consultant voice  

Never choose novelty over usefulness.  
Never choose density over clarity.  
Never choose decoration over meaning.

---

## 7. Stop line

These principles are binding for all future Result Experience V2 implementation.
