# 08 — Product Polish Roadmap

Version: 1.0.0  
Status: **OFFICIAL — Design Reference**  
Date: 2026-08-08  
Sprint: Product Polish V1 · Sprint A (architecture complete)  

---

## 1. Purpose

Define **implementation order** for Product Polish V1 after this architecture pack.

Architecture (Sprint A) is documentation only. Later phases may touch Presentation **within** frozen Foundation / Narrative / Knowledge / Portal-route constraints — only when Product authorizes implementation sprints.

Commercial V1 remains **RC1** until Product GO (separate gate).

---

## 2. Phase overview

```
Phase 1  Layout emphasis (within PACK_06)
        ↓
Phase 2  Narrative presentation
        ↓
Phase 3  Visual polish
        ↓
Phase 4  Micro interactions
```

Do not skip phases to chase polish. Hierarchy before decoration.

---

## 3. Phase 1 — Layout

| Item | Detail |
|------|--------|
| **Goal** | Make Information Hierarchy and Screen Priority visible inside frozen zones |
| **Includes** | Band emphasis mapping; Primary vs Secondary Rec separation; demote chart dominance; first-viewport composition intent |
| **Uses** | `02`, `03`, `04`, `06` |
| **Must not** | Reorder PACK_06 rows; add zones/routes; change Design System spacing scale |
| **Exit** | Hero/Primary/Secondary recognizable in review |

---

## 4. Phase 2 — Narrative presentation

| Item | Detail |
|------|--------|
| **Goal** | Align customer-facing copy structure to commercial reading flow |
| **Includes** | Density caps; Exec/Rec structure enforcement in presentation; commercial wording consistency; progressive disclosure of long prose |
| **Uses** | `03`, `05`, `06`, `07` |
| **Must not** | Edit Knowledge CSV as “copyfix”; redesign Narrative Engine; invent facts |
| **Exit** | Who am I → Strengths → Challenges → Career → Actions readable in one pass |

---

## 5. Phase 3 — Visual polish

| Item | Detail |
|------|--------|
| **Goal** | Quiet Reference; strengthen consulting calm; reduce calculator chrome |
| **Includes** | Emphasis using existing DS roles; chart/table quieting; card clarity; whitespace intent |
| **Uses** | `04`, `05` + Design System (frozen tokens) |
| **Must not** | New color/type scales; marketing landing aesthetics; decorative noise |
| **Exit** | Visual QA vs Experience Principles pass |

---

## 6. Phase 4 — Micro interactions

| Item | Detail |
|------|--------|
| **Goal** | Support progressive disclosure and CTA clarity with minimal motion |
| **Includes** | Expand/collapse; scroll affordance to Rec; hover/focus already in DS; soft Primary CTA emphasis |
| **Uses** | `07`, `05` |
| **Must not** | Motion for decoration; animation that delays advice; new interaction paradigms outside DS |
| **Exit** | CTAs clear; disclosure usable on desktop + mobile |

---

## 7. Cross-phase gates

| Gate | Required |
|------|----------|

| Foundation compliance checklist | Before UI merge |
| No Engine / Knowledge / Narrative architecture edits | Continuous |

| Commercial V1 RC1 human gate | Independent of polish phases |

- No phase requires unfreezing Engines / Foundation / Knowledge / Narrative / routes.
