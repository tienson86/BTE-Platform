# Feature Spec — Identity Report

| Field | Value |
|-------|-------|
| Document | FEATURE_SPEC |
| Version | 1.0.0 |

---

## 1. Objective

Deliver one commercial report that answers **Who am I?** with enough clarity that a paying customer can act without reading domain modules.

## 2. Inputs (interpretation only)

| Input | Role in Identity |
|-------|------------------|
| Strength Interpretation | Capacity, endurance, recovery posture |
| Ten Gods Interpretation | Operating style, pressure, responsibility rhythm |
| Destiny Structure Interpretation | Long-frame organization / life orientation |
| Balance Strategy Interpretation | What keeps identity sustainable |
| Master Consulting | Cross-domain synthesis voice / priorities |

**Forbidden inputs:** raw scores, rule IDs, matched rules, pillar dumps, engine traces.

## 3. Non-goals

- Not a full life timeline
- Not a career-only report
- Not a relationship-only report
- Not a textbook of Ten Gods
- Not a reprint of Parts 01–04 / Part 08

## 4. Output contract

Nine fixed sections (see CONTENT_STRUCTURE.md), ending with a 5–7 sentence Identity Summary.

## 5. Audience

Paying customer · non-technical · Vietnamese Customer Mode (CASE-0001 sample).

## 6. Success criteria

Customer Test (must be answerable from this report alone):

1. Who am I?  
2. What makes me strong?  
3. What usually holds me back?  
4. What kind of environment suits me?  
5. What should I start doing today?  

## 7. Production note

This feature specification is product-complete. Runtime wiring into the orchestrator is a later implementation task and is **not** required for Feature 01 document COMPLETE.
